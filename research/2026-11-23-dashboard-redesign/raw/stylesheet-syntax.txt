## Style Rules[](https://doc.qt.io/qt-6/stylesheet-syntax.html#style-rules "Direct link to this headline")

Style sheets consist of a sequence of style rules. A _style rule_ is made up of a selector and a declaration. The _selector_ specifies which widgets are affected by the rule; the _declaration_ specifies which properties should be set on the widget. For example:

## Selector Types[](https://doc.qt.io/qt-6/stylesheet-syntax.html#selector-types "Direct link to this headline")

All the examples so far used the simplest type of selector, the Type Selector. Qt Style Sheets support all the [selectors defined in CSS2](http://www.w3.org/TR/REC-CSS2/selector.html#q1). The table below summarizes the most useful types of selectors.

| Selector | Example | Explanation |
| --- | --- | --- |
| Universal Selector | `*` | Matches all widgets. |
| Type Selector | `QPushButton` | Matches instances of [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) and of its subclasses. |
| Property Selector | `QPushButton[flat="false"]` | Matches instances of [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) that are not [flat](https://doc.qt.io/qt-6/qpushbutton.html#flat-prop). You may use this selector to test for any Qt [property](https://doc.qt.io/qt-6/properties.html) that supports [QVariant::toString](https://doc.qt.io/qt-6/qvariant.html#toString)() (see the [toString](https://doc.qt.io/qt-6/qvariant.html#toString)() function documentation for details). In addition, the special `class` property is supported, for the name of the class. This selector may also be used to test dynamic properties. For more information on customization using dynamic properties, refer to [Customizing Using Dynamic Properties](https://doc.qt.io/qt-6/stylesheet-examples.html#customizing-using-dynamic-properties). Instead of `=`, you can also use `~=` to test whether a Qt property of type [QStringList](https://doc.qt.io/qt-6/qstringlist.html) contains a given [QString](https://doc.qt.io/qt-6/qstring.html). **Warning:**If the value of the Qt property changes after the style sheet has been set, it might be necessary to force a style sheet recomputation. One way to achieve this is to unset the style sheet and set it again. |
| Class Selector | `.QPushButton` | Matches instances of [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html), but not of its subclasses. This is equivalent to `*[class~="QPushButton"]`. |
| ID Selector | `QPushButton#okButton` | Matches all [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) instances whose [object name](https://doc.qt.io/qt-6/qobject.html#objectName-prop) is `okButton`. |
| Descendant Selector | `QDialog QPushButton` | Matches all instances of [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) that are descendants (children, grandchildren, etc.) of a [QDialog](https://doc.qt.io/qt-6/qdialog.html). |
| Child Selector | `QDialog > QPushButton` | Matches all instances of [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) that are direct children of a [QDialog](https://doc.qt.io/qt-6/qdialog.html). |

## Sub-Controls[](https://doc.qt.io/qt-6/stylesheet-syntax.html#sub-controls "Direct link to this headline")

For styling complex widgets, it is necessary to access subcontrols of the widget, such as the drop-down button of a [QComboBox](https://doc.qt.io/qt-6/qcombobox.html) or the up and down arrows of a [QSpinBox](https://doc.qt.io/qt-6/qspinbox.html). Selectors may contain _subcontrols_ that make it possible to restrict the application of a rule to specific widget subcontrols. For example:

`QComboBox::drop-down { image: url(dropdown.png) }`

The above rule styles the drop-down button of all [QComboBox](https://doc.qt.io/qt-6/qcombobox.html)es. Although the double-colon (`::`) syntax is reminiscent of CSS3 Pseudo-Elements, Qt Sub-Controls differ conceptually from these and have different cascading semantics.

Sub-controls are always positioned with respect to another element - a reference element. This reference element could be the widget or another Sub-control. For example, the [::drop-down](https://doc.qt.io/qt-6/stylesheet-reference.html#drop-down-sub) of a [QComboBox](https://doc.qt.io/qt-6/qcombobox.html) is placed, by default, in the top right corner of the Padding rectangle of the [QComboBox](https://doc.qt.io/qt-6/qcombobox.html). The [::drop-down](https://doc.qt.io/qt-6/stylesheet-reference.html#drop-down-sub) is placed, by default, in the Center of the Contents rectangle of the [::drop-down](https://doc.qt.io/qt-6/stylesheet-reference.html#drop-down-sub) Sub-control. See the [List of Stylable Widgets](https://doc.qt.io/qt-6/stylesheet-reference.html#list-of-stylable-widgets) below for the Sub-controls to use to style a widget and their default positions.

The origin rectangle to be used can be changed using the [subcontrol-origin](https://doc.qt.io/qt-6/stylesheet-reference.html#subcontrol-origin-prop) property. For example, if we want to place the drop-down in the margin rectangle of the [QComboBox](https://doc.qt.io/qt-6/qcombobox.html) instead of the default Padding rectangle, we can specify:

The alignment of the drop-down within the Margin rectangle is changed using [subcontrol-position](https://doc.qt.io/qt-6/stylesheet-reference.html#subcontrol-position-prop) property.

The [width](https://doc.qt.io/qt-6/stylesheet-reference.html#width-prop) and [height](https://doc.qt.io/qt-6/stylesheet-reference.html#height-prop) properties can be used to control the size of the Sub-control. Note that setting a [image](https://doc.qt.io/qt-6/stylesheet-reference.html#image-prop) implicitly sets the size of a Sub-control.

The relative positioning scheme ([position](https://doc.qt.io/qt-6/stylesheet-reference.html#position-prop) : relative), allows the position of the Sub-Control to be offset from its initial position. For example, when the [QComboBox](https://doc.qt.io/qt-6/qcombobox.html)'s drop-down button is pressed, we might like the arrow inside to be offset to give a "pressed" effect. To achieve this, we can specify:

```
QComboBox::down-arrow {
    image: url(down_arrow.png);
}
QComboBox::down-arrow:pressed {
    position: relative;
    top: 1px; left: 1px;
}
```

The absolute positioning scheme ([position](https://doc.qt.io/qt-6/stylesheet-reference.html#position-prop) : absolute), allows the position and size of the Sub-control to be changed with respect to the reference element.

Once positioned, they are treated the same as widgets and can be styled using the [box model](https://doc.qt.io/qt-6/stylesheet-customizing.html#the-box-model).

See the [List of Sub-Controls](https://doc.qt.io/qt-6/stylesheet-reference.html#list-of-sub-controls) below for a list of supported sub-controls, and [Customizing the QPushButton's Menu Indicator Sub-Control](https://doc.qt.io/qt-6/stylesheet-examples.html#customizing-the-qpushbutton-s-menu-indicator-sub-control) for a realistic example.

**Note:**With complex widgets such as [QComboBox](https://doc.qt.io/qt-6/qcombobox.html) and [QScrollBar](https://doc.qt.io/qt-6/qscrollbar.html), if one property or sub-control is customized, **all** the other properties or sub-controls must be customized as well.

Both rules apply to [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) instances (since [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) inherits [QAbstractButton](https://doc.qt.io/qt-6/qabstractbutton.html)) and there is a conflict for the [color](https://doc.qt.io/qt-6/stylesheet-reference.html#color-prop) property. Because [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) inherits [QAbstractButton](https://doc.qt.io/qt-6/qabstractbutton.html), it might be tempting to assume that `QPushButton` is more specific than `QAbstractButton`. However, for style sheet computations, all Type Selectors have the same specificity, and the rule that appears last takes precedence. In other words, [color](https://doc.qt.io/qt-6/stylesheet-reference.html#color-prop) is set to `gray` for all [QAbstractButton](https://doc.qt.io/qt-6/qabstractbutton.html)s, including [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html)s. If we really want [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html)s to have red text, we can always reorder the rules.

For determining the specificity of a rule, Qt Style Sheets follow the [CSS2 Specification](http://www.w3.org/TR/REC-CSS2/cascade.html#specificity):

> _A selector's specificity is calculated as follows:_
> 
> 
> *   _count the number of ID attributes in the selector (= a)_
> *   _count the number of other attributes and pseudo-classes in the selector (= b)_
> *   _count the number of element names in the selector (= c)_
> *   _ignore pseudo-elements [i.e., [subcontrols](https://doc.qt.io/qt-6/stylesheet-reference.html#list-of-sub-controls)]._
> 
> 
> _Concatenating the three numbers a-b-c (in a number system with a large base) gives the specificity._
> 
> 
> _Some examples:_
> 
> 
> 
> ```
> *             {}  /* a=0 b=0 c=0 -> specificity =   0 */
> LI            {}  /* a=0 b=0 c=1 -> specificity =   1 */
> UL LI         {}  /* a=0 b=0 c=2 -> specificity =   2 */
> UL OL+LI      {}  /* a=0 b=0 c=3 -> specificity =   3 */
> H1 + *[REL=up]{}  /* a=0 b=1 c=1 -> specificity =  11 */
> UL OL LI.red  {}  /* a=0 b=1 c=3 -> specificity =  13 */
> LI.red.level  {}  /* a=0 b=2 c=1 -> specificity =  21 */
> #x34y         {}  /* a=1 b=0 c=0 -> specificity = 100 */
> ```

## Cascading[](https://doc.qt.io/qt-6/stylesheet-syntax.html#cascading "Direct link to this headline")

Style sheets can be set on the [QApplication](https://doc.qt.io/qt-6/qapplication.html), on parent widgets, and on child widgets. An arbitrary widget's effective style sheet is obtained by merging the style sheets set on the widget's ancestors (parent, grandparent, etc.), as well as any style sheet set on the [QApplication](https://doc.qt.io/qt-6/qapplication.html).

When conflicts arise, the widget's own style sheet is always preferred to any inherited style sheet, irrespective of the specificity of the conflicting rules. Likewise, the parent widget's style sheet is preferred to the grandparent's, etc.

One consequence of this is that setting a style rule on a widget automatically gives it precedence over other rules specified in the ancestor widgets' style sheets or the [QApplication](https://doc.qt.io/qt-6/qapplication.html) style sheet. Consider the following example. First, we set a style sheet on the [QApplication](https://doc.qt.io/qt-6/qapplication.html):

`qApp->setStyleSheet("QPushButton { color: white }");`

Then we set a style sheet on a [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) object:

`myPushButton->setStyleSheet("* { color: blue }");`

The style sheet on the [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) forces the [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) (and any child widget) to have blue text, in spite of the more specific rule set provided by the application-wide style sheet.

The result would have been the same if we had written

`myPushButton->setStyleSheet("color: blue");`

except that if the [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) had children (which is unlikely), the style sheet would have no impact on them.

Style sheet cascading is a complex topic. Refer to the [CSS2 Specification](http://www.w3.org/TR/CSS2/cascade.html#cascade) for the gory details. Be aware that Qt currently doesn't implement `!important`.

## Inheritance[](https://doc.qt.io/qt-6/stylesheet-syntax.html#inheritance "Direct link to this headline")

In classic CSS, when font and color of an item is not explicitly set, it gets automatically inherited from the parent. By default, when using Qt Style Sheets, a widget does **not** automatically inherit its font and color setting from its parent widget.

For example, consider a [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) inside a [QGroupBox](https://doc.qt.io/qt-6/qgroupbox.html):

`qApp->setStyleSheet("QGroupBox { color: red; } ");`

The [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html) does not have an explicit color set. Hence, instead of inheriting color of its parent [QGroupBox](https://doc.qt.io/qt-6/qgroupbox.html), it has the system color. If we want to set the color on a [QGroupBox](https://doc.qt.io/qt-6/qgroupbox.html) and its children, we can write:

`qApp->setStyleSheet("QGroupBox, QGroupBox * { color: red; }");`

In contrast, setting a font and palette using [QWidget::setFont](https://doc.qt.io/qt-6/qwidget.html#font-prop)() and [QWidget::setPalette](https://doc.qt.io/qt-6/qwidget.html#palette-prop)() propagates to child widgets.

If you would prefer that the font and palette propagate to child widgets, you can set the [Qt::AA_UseStyleSheetPropagationInWidgetStyles](https://doc.qt.io/qt-6/qt.html#ApplicationAttribute-enum) flag, like this:

Usage:

When the widget-style font and palette propagation is enabled, font and palette changes made through Qt Style Sheets will behave as if the user had manually called the corresponding [QWidget::setPalette](https://doc.qt.io/qt-6/qwidget.html#palette-prop)() and [QWidget::setFont](https://doc.qt.io/qt-6/qwidget.html#font-prop)() methods on all of the QWidgets targeted by the style sheet.

*   Changes made by a style sheet are propagated. They are pushed to all widgets matching the style sheet once, at the time the change is made.
*   Changes made by calling [QWidget::setPalette](https://doc.qt.io/qt-6/qwidget.html#palette-prop)() or [QWidget::setFont](https://doc.qt.io/qt-6/qwidget.html#font-prop)() are inherited. They are inherited by all existing and future children, where the respective brush or font hasn't been explicitly set.

The Type Selector can be used to style widgets of a particular type. For example,

```
class MyPushButton : public QPushButton {
    // ...
};

// ...
void someFunction()
{
    qApp->setStyleSheet("MyPushButton { background: yellow; }");
    //...
```

Qt Style Sheet uses QObject::className() of the widget to determine when to apply the Type Selector. When custom widgets are inside namespaces, the QObject::className() returns <namespace>::<classname>. This conflicts with the syntax for [Sub-Controls](https://doc.qt.io/qt-6/stylesheet-syntax.html#sub-controls). To overcome this problem, when using the Type Selector for widgets inside namespaces, we must replace the `::` with `--`. For example,

```
namespace ns {
    class MyPushButton : public QPushButton {
        // ...
    };
}

// ...
void someMethod()
{
    qApp->setStyleSheet("ns--MyPushButton { background: yellow; }");
    //...
```

## Setting QObject Properties[](https://doc.qt.io/qt-6/stylesheet-syntax.html#setting-qobject-properties "Direct link to this headline")

From 4.3 and above, any designable [Q_PROPERTY](https://doc.qt.io/qt-6/qobject.html#Q_PROPERTY) can be set using the qproperty-<property name> syntax.

For example,

```
MyLabel { qproperty-pixmap: url(pixmap.png); }
MyGroupBox { qproperty-titleColor: rgb(100, 200, 100); }
QPushButton { qproperty-iconSize: 20px 20px; }
```

If the property references an enum declared with [Q_ENUM](https://doc.qt.io/qt-6/qobject.html#Q_ENUM), you should reference its constants by name, not their numeric value.

**Note:**Use the qproperty syntax with care, as it modifies the widget that is being painted. Also, the qproperty syntax is evaluated only once, which is when the widget is polished by the style. This means that any attempt to use them in pseudo-states such as [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html):hover, will not work.
