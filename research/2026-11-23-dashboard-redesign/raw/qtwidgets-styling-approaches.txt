Title: Styling Approaches for Qt Widgets | Qt Widgets

URL Source: https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html

Markdown Content:
Qt Widgets offers three ways to change how widgets look:

*   A [style](https://doc.qt.io/qt-6/qstyle.html) draws every widget. Subclass [QProxyStyle](https://doc.qt.io/qt-6/qproxystyle.html) to adjust the platform style, or [QCommonStyle](https://doc.qt.io/qt-6/qcommonstyle.html) to implement a complete custom look. This is the mechanism that Qt's own styles use, and the one to use in production applications.
*   [StyleKit](https://doc.qt.io/qt-6/qtlabsstylekit-index.html) describes a design declaratively in QML and applies it to widgets through [QStyleKitStyle](https://doc.qt.io/qt-6/qstylekitstyle.html), a [QStyle](https://doc.qt.io/qt-6/qstyle.html) implementation. The same style file also styles Qt Quick Controls.
*   [Style sheets](https://doc.qt.io/qt-6/stylesheet.html) override individual visual properties with CSS-like rules. They are a tool for prototyping and for small, local adjustments, not for the production look of an application.

This page explains what each approach costs and when to choose it.

## Choose an approach[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#choose-an-approach "Direct link to this headline")

The following table maps a styling goal to the mechanism that fits it.

| Goal | Approach |
| --- | --- |
| Keep the native look but change a few details, such as a metric, a color, or a style hint | A [QProxyStyle](https://doc.qt.io/qt-6/qproxystyle.html) subclass |
| Give the application its own look, independent of the platform style, for example, on an embedded device | A [QCommonStyle](https://doc.qt.io/qt-6/qcommonstyle.html) subclass or a StyleKit style |
| Share one design between Qt Widgets and Qt Quick Controls | A StyleKit style |
| Offer light and dark variants of the same design | A different [QPalette](https://doc.qt.io/qt-6/qpalette.html) for the same style, or a StyleKit theme |
| Try out colors, borders, and spacing quickly, or restyle a single widget during development | A style sheet |

## Implement a style for production applications[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#implement-a-style-for-production-applications "Direct link to this headline")

A [QStyle](https://doc.qt.io/qt-6/qstyle.html) subclass draws widgets directly with [QPainter](https://doc.qt.io/qt-6/qpainter.html), using the information in the [QStyleOption](https://doc.qt.io/qt-6/qstyleoption.html) that each widget passes to the style. A style has full control over every element, from a button bevel to the branches of a tree view, and it exercises that control at the cost of an ordinary paint operation: there are no rules to match and no per-widget state to recompute.

Choose the base class according to how much you want to change:

*   [QProxyStyle](https://doc.qt.io/qt-6/qproxystyle.html) wraps another style, by default the platform style, and lets you override selected functions such as [drawPrimitive](https://doc.qt.io/qt-6/qstyle.html#drawPrimitive)(), [pixelMetric](https://doc.qt.io/qt-6/qstyle.html#pixelMetric)(), or [styleHint](https://doc.qt.io/qt-6/qstyle.html#styleHint)(). Everything you don't override keeps the native look and behavior. Use it to adjust the platform style.
*   [QCommonStyle](https://doc.qt.io/qt-6/qcommonstyle.html) implements the behavior that all of Qt's styles share and leaves the drawing to you. Use it as the base for a complete custom look. [Styles and Style Aware Widgets](https://doc.qt.io/qt-6/style-reference.html) walks through the style elements and shows how each widget is drawn.

Set the style once, before the application creates its windows:

```
#include <QtWidgets>

#include "customstyle.h"

int main(int argc, char *argv[])
{
    QApplication::setStyle(new CustomStyle);
    QApplication app(argc, argv);
    QSpinBox spinBox;
    spinBox.show();
    return app.exec();
}
```

Draw with the colors from the [QPalette](https://doc.qt.io/qt-6/qpalette.html) in the style option rather than with hard-coded colors. The same style then produces a light and a dark variant of the design from two palettes, without switching styles. Qt's Fusion style works this way.

To let users select the style from the command line with the `-style` option, or to share it between applications, build the style as a plugin. See [QStylePlugin](https://doc.qt.io/qt-6/qstyleplugin.html) and [How to Create Qt Plugins](https://doc.qt.io/qt-6/plugins-howto.html).

## Describe the design in QML with StyleKit[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#describe-the-design-in-qml-with-stylekit "Direct link to this headline")

[StyleKit](https://doc.qt.io/qt-6/qtlabsstylekit-index.html) is a declarative styling system. A style is a QML file whose root object is a `Style`, which sets colors, sizes, radii, borders, and state-dependent variations for each control type. Properties propagate through a control hierarchy, so a value set once on `abstractButton` applies to every kind of button, and a style can define several named themes.

[QStyleKitStyle](https://doc.qt.io/qt-6/qstylekitstyle.html) is a [QStyle](https://doc.qt.io/qt-6/qstyle.html) implementation that reads such a style and paints widgets with [QPainter](https://doc.qt.io/qt-6/qpainter.html). Qt Quick takes no part in the rendering. The same `Style` file also styles Qt Quick Controls, so an application that uses both toolkits maintains one design definition. Themes defined in the style are selected with [setThemeName](https://doc.qt.io/qt-6/qstylekitstyle.html#setThemeName)().

[QStyleKitStyle](https://doc.qt.io/qt-6/qstylekitstyle.html) is available since Qt 6.12. StyleKit is a Qt Labs module, and its API may change between Qt releases. The [StyleKit Widgets Example](https://doc.qt.io/qt-6/qtlabsstylekit-stylekitwidgets-example.html) shows a widget application with several StyleKit styles and themes.

## Use style sheets for prototyping[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#use-style-sheets-for-prototyping "Direct link to this headline")

[Qt Style Sheets](https://doc.qt.io/qt-6/stylesheet.html) change the appearance of widgets through rules in a CSS-like syntax, without writing C++. They are convenient for trying out a design: edit a `.qss` file and restart the application, or pass the file with the `-stylesheet` command-line option, and [Qt Widgets Designer](https://doc.qt.io/qt-6/stylesheet-designer.html) previews the same rules. They are also the quickest way to mark a single widget, such as a mandatory field with a yellow background.

Style sheets have costs that make them unsuitable as the styling mechanism of a production application:

*   **Every affected widget is drawn through the style sheet engine.** When a style sheet is set, [QWidget::style](https://doc.qt.io/qt-6/qwidget.html#style)() returns a style sheet style that wraps the underlying [style](https://doc.qt.io/qt-6/qstyle.html). For each widget it matches the selectors against the widget's class, object name, properties, and state, computes the rendering rules, and caches them per widget. The memory and processing cost grows with the number of widgets and rules.
*   **Changing a style sheet repolishes everything it applies to.** Each call to [QApplication::setStyleSheet](https://doc.qt.io/qt-6/qapplication.html#styleSheet-prop)() discards the caches and repolishes every widget in the application, which recomputes fonts, palettes, geometry, and size hints and can visibly flicker. Don't build theme switching on style sheets.
*   **A partial rule discards the native look.** When a rule requests something the native style cannot honor, such as a background color for a [QPushButton](https://doc.qt.io/qt-6/qpushbutton.html), the style sheet engine draws the whole element itself, without the native decoration. You then have to specify borders, padding, and every state yourself, and a small adjustment grows into a complete description of the look. See [Customizing Qt Widgets Using Style Sheets](https://doc.qt.io/qt-6/stylesheet-customizing.html).
*   **Selectors couple the design to implementation details.** Rules match class names, object names, and property values. Renaming an object or replacing a widget class silently stops the rule from matching. Rules don't affect custom widgets that paint without the style.
*   **Style sheets win over programmatic settings.** A style sheet overrides fonts, palettes, and item colors set with functions such as [QWidget::setFont](https://doc.qt.io/qt-6/qwidget.html#font-prop)() or [QTreeWidgetItem::setBackground](https://doc.qt.io/qt-6/qtreewidgetitem.html#setBackground)(), so the styling of a widget is no longer visible in one place.

For a side-by-side comparison of style sheets and [QStyle](https://doc.qt.io/qt-6/qstyle.html) subclasses, see the KDAB article [Say No to Qt Style Sheets](https://www.kdab.com/say-no-to-qt-style-sheets/).

### If you use style sheets anyway[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#if-you-use-style-sheets-anyway "Direct link to this headline")

For a prototype, or for the few local adjustments that a production application needs, keep the style sheet manageable:

*   **Keep the rules in a `.qss` file**, bundled with [the Qt resource system](https://doc.qt.io/qt-6/resources.html). Set it once on the application with [QApplication::setStyleSheet](https://doc.qt.io/qt-6/qapplication.html#styleSheet-prop)(), before the first window is shown, and leave it in place. Reserve [QWidget::setStyleSheet](https://doc.qt.io/qt-6/qwidget.html#styleSheet-prop)() for adjustments that are truly local to one widget and its children.
*   **Don't assemble style sheets from C++ strings.** A style sheet set on a widget is parsed once for every widget it's set on, not once for every string, and each call to [QWidget::setStyleSheet](https://doc.qt.io/qt-6/qwidget.html#styleSheet-prop)() repolishes the widget and all its children, even when the string didn't change. A string built with [QString::arg](https://doc.qt.io/qt-6/qstring.html#arg)() to reflect data, such as a red border for an invalid value, repolishes the widget on every update. Instead, express the difference with a [selector](https://doc.qt.io/qt-6/stylesheet-syntax.html) on an object name or a Qt property in the one style sheet, and re-evaluate it as described in [Customizing Using Dynamic Properties](https://doc.qt.io/qt-6/stylesheet-examples.html#customizing-using-dynamic-properties).
*   **Don't hard-code colors.** A literal color such as `#ffffff` fits one theme. Use `palette(window)`, `palette(text)`, and the other [palette roles](https://doc.qt.io/qt-6/stylesheet-reference.html#paletterole) so that the style sheet follows the application palette, including a dark color scheme.
*   **Don't size everything in pixels.** A `px` value scales with the display but not with the user's font. Use `em` and `ex`[lengths](https://doc.qt.io/qt-6/stylesheet-reference.html#length) for paddings, margins, and sizes that should follow the font, and `pt` for font sizes.

### Move from a style sheet to a style[](https://doc.qt.io/qt-6/qtwidgets-styling-approaches.html#move-from-a-style-sheet-to-a-style "Direct link to this headline")

When a prototype turns into a product, transfer the design to a style. Most style sheet constructs have a direct counterpart:

| Style sheet | [QStyle](https://doc.qt.io/qt-6/qstyle.html) | StyleKit |
| --- | --- | --- |
| Colors | [QPalette](https://doc.qt.io/qt-6/qpalette.html) roles, read from [QStyleOption::palette](https://doc.qt.io/qt-6/qstyleoption.html#palette-var) | Color properties of the control, or a theme |
| `border`, `padding`, `margin` | [pixelMetric](https://doc.qt.io/qt-6/qstyle.html#pixelMetric)() and [subElementRect](https://doc.qt.io/qt-6/qstyle.html#subElementRect)() | Border and size properties of the control |
| Pseudo-states such as `:hover` and `:pressed` | [QStyle::State](https://doc.qt.io/qt-6/qstyle.html#StateFlag-enum) flags in [QStyleOption::state](https://doc.qt.io/qt-6/qstyleoption.html#state-var) | State groups such as `hovered` and `pressed` |
| Subcontrols such as `::indicator` | [drawPrimitive](https://doc.qt.io/qt-6/qstyle.html#drawPrimitive)() and [drawControl](https://doc.qt.io/qt-6/qstyle.html#drawControl)() for the element | Delegate properties such as `indicator` |
